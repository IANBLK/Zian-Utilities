# M2 global quest: two objectives (alpha.13)

This is an opt-in quest trial for Youer 1.21.1. The alpha.13 mod is required on both server and client. Start with `-Dzianutilities.globalQuestTestEnabled=true` before `-jar` and leave the older capture/shared mission flags off. Do **not** set `-Dzianutilities.globalQuestRewardTestEnabled=true` until the capture, battle, restart, and two-player checks below pass on Youer. The first flag only records progress; the second permits real AVECOINS credits for windows created after it is enabled.

`/zian` opens the main menu. Its **Misiones** card opens the same screen as `/zian quest`; **Gachas** is visible but inactive. The quest screen shows the current target species with its Cobblemon model, capture status, the five battle steps, rewards, and the next reset time in Ecuador. A capture before acceptance does not count. The same species is offered to everyone. The capture objective needs one Pokémon of that species from an active generation. The battle objective needs five **distinct wild battle victories** by that player; a captured wild Pokémon, PvP, and NPC battles do not count. At 00:00, 03:00, 06:00, and so on in `America/Guayaquil`, the offer changes and unfinished progress expires. A player must accept again. Generation changes replace the shared offer and require a new acceptance, so a disabled target cannot strand a mission. Completed objectives cannot credit twice during the same window, even if generations change. The client sends only navigation and accept/refresh requests; the server chooses the species and computes progress and rewards.

The global offer and the currently active reward definition live at `world/data/zianutilities/global_quest_v1/offer.properties`. Each accepted player has at most one current and one previous small progress file under `players/`. Two deterministic reward-claim IDs per player/window use the existing `world/data/zianutilities/reward_claims/` journal and `/zian reward inspect <claimId>` admin command. Terminal claimed records older than the retained previous window are removed on rollover. Uncertain claims are deliberately retained for audit, and never replayed automatically. Players who never accept do not get progress files.

The generated `world/data/zianutilities/global_quest_v1/config.properties` defines `capture.currency`, `capture.amount`, `battle.currency`, and `battle.amount`. Defaults are one `avecoins:coppercoin` for each objective. Set a positive integer amount and an AVECOINS-managed currency ID. `species.gen1` through `species.gen9` are comma-separated curated target pools; the mod ignores entries that Cobblemon cannot resolve to that generation. Edit this file while the server is stopped. Reward and species changes take effect on the **next** three-hour offer. A generation change during the current window may select a new target, but keeps that window's reward amounts. Implemented species are not necessarily obtainable in every biome or server configuration; review and adjust the pools before using the mission in production.

Recommended alpha.13 visual test: install the exact same alpha.13 JAR in Youer's `mods` folder and in a NeoForge 1.21.1 client's `mods` folder; remove older Zian Utilities JARs. Restart both. Keep only `-Dzianutilities.globalQuestTestEnabled=true`; leave the reward flag off. A client without alpha.13 should be refused at connection. With Gen7 active, `/zian` should show the main menu with an enabled **Misiones** button and disabled **Gachas** button. Open Misiones and verify the target Pokémon model and species name. **Inicio** must return to the main menu. `/zian quest` must still open Misiones directly. Clicking **Actualizar** should preserve the server's progress. The accept button should work once, and reopen after a server restart should show the same state. If the visual screen crashes, retain the client crash log for diagnosis and revert server and client to the previously tested JAR together.

Full Youer test with two non-OP players and Gen7 active:

1. Start with only `globalQuestTestEnabled=true`. Both players open `/zian quest` and see the same species. Only one accepts. Capture the named species on both accounts; only the accepting account should complete. Accept on the second account, capture the named species, and verify its own checkmark.
2. Win five separate wild battles on one accepted account. Verify 1/5 through 5/5. Reopen the menu and restart the server with the same JAR; progress must persist. Capturing a wild Pokémon in battle, fighting a player/NPC, or repeating one battle event must not advance.
3. Change active generations and check that both accounts see the same new target, with a fresh acceptance. After a natural three-hour boundary, the new offer starts with no progress.
4. Once those pass, stop the server and add `-Dzianutilities.globalQuestRewardTestEnabled=true`. Start a **new** three-hour window for an unambiguous payment test. Each completed objective should credit its configured reward once. Reopen the menu, restart, repeat `/zian quest`, and verify the balance is unchanged. If the log reports `RECOVERY_REQUIRED`, do not create a replacement claim; retain the files and inspect the audit state.

Youer runtime verification is required before this trial is considered production-ready. This feature does not modify the existing alpha.10 shared-capture mission or AVECOINS admin probe.
