# M2: three-capture, global three-hour cycle (alpha.9.1)

This is a separate opt-in Youer 1.21.1 trial. It does not change the earlier one-capture assignment, generation control, or AVECOINS balances. The three objectives are three distinct Pokémon captures from whichever generations are active **when captured**. There are no species or type requirements, and completing a cycle grants no rewards.

Start Java with `-Dzianutilities.captureCycleTestEnabled=true` before `-jar`. Leave the older `captureMissionTestEnabled`, `captureTrialTestEnabled`, and `captureProbeEnabled` flags unset. The new commands are `/zian quest cycle start` (operator, self), `/zian quest cycle assign <online player>` (operator), and `/zian quest cycle status` (each player can inspect their own cycle). Assignment is explicit. Repeating assignment during the current three-hour window does not reset progress or the timer.

All players share fixed three-hour windows at 00:00, 03:00, 06:00, 09:00, 12:00, 15:00, 18:00 and 21:00 in `America/Guayaquil`. The Java runtime's default timezone does not change this schedule. A player assigned near a boundary receives only the time remaining in that window. At expiry, the next status query, assignment, or capture archives the old cycle and opens the window containing the current time. Partial progress (1/3 or 2/3) is archived but never carried over; the new cycle begins at 0/3. A completed cycle stays at 3/3 until the boundary, with no second completion or reward in that window. If all generations are disabled, progress pauses while the clock continues. A six-hour Youer restart does not reset or extend any window; time spent offline does not shift the schedule. Archived cycles are kept under `world/data/zianutilities/quest_assignments/capture_three_global_v1/history/`. The earlier `capture_three_active_v1` and `capture_any_active_v1` files are untouched.

For a short acceptance run, assign one operator and one non-operator, capture three separate Pokémon from active generations on one account, and check `status` after every capture: 0/3, 1/3, 2/3, 3/3. A fourth capture must leave 3/3. The second account's progress must remain independent. Restart with the same JAR and flag before a boundary and verify progress, cycle ID, and balance persist. Then remove only the new flag, restart, and verify the cycle command disappears while `/zian generation active` still works for both players. Exact boundary and partial-progress reset are covered by clock-controlled core tests; a natural server rollover can be checked later without altering the system clock.
